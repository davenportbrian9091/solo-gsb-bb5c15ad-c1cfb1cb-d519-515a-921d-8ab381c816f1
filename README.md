# 显微图像纹理分区审阅台

本地运行的灰度显微图像纹理分区（texture segmentation）审阅工具：上传显微图并设置像素尺度，
系统计算**局部梯度方向场**，依据**方向一致性**与**强度阈值**生成候选纹理区域，采用
**标记控制的分水岭 + 分水岭式区域合并**避免相邻区域粘连，并以红色标出**低置信度边界**。
网页上可叠加查看原图 / 方向场 / 区域轮廓，拖动阈值实时重算，结果以**版本号**保存、可回溯对比。

技术栈：Node.js（Express）+ SQLite（better-sqlite3）+ 原生 Canvas/PNG 网页界面，无前端构建步骤。

## 一条命令启动

需要 Docker 与 Docker Compose v2：

```bash
docker compose up --build
```

启动后用浏览器访问：

> **http://localhost:8080**

（端口映射在 `docker-compose.yml` 中，改为如 `"9090:8080"` 即可换宿主机端口。）

停止：`Ctrl+C`，或在另一终端执行 `docker compose down`。上传的图像与 SQLite 数据库保存在宿主机 `./data` 目录，容器重建不丢数据。

## 不用 Docker 直接运行

需要 Node.js ≥ 20：

```bash
npm install
npm start
# 同样访问 http://localhost:8080
```

环境变量：`PORT`（默认 8080）、`DATA_DIR`（默认 `./data`）。

## 使用说明

1. **上传**：在左栏选择一张显微图像（彩色图自动转灰度），可同时填写像素尺度（µm/px，对应原始分辨率），上传后即可在标题栏随时修改尺度。长边超过 1000px 的图像分析时会自动等比缩小（区域面积等物理尺寸按尺度自动换算到分析分辨率）。
2. **调阈值**（拖动后约 200ms 自动重算）：
   - **梯度强度阈值**：按结构张量窗口能量的分位数截取候选纹理像素（0–95 分位），值越高候选像素越少；
   - **方向一致性阈值**：结构张量特征值各向异性比 `(λ₁−λ₂)/(λ₁+λ₂)`，方向越一致越接近 1；
   - **区域合并阈值**：两个区域平均纹理方向角差小于 `阈值 × 90°` 时合并（默认 0.30 → 27°），用于把被暗间隔分开但走向一致的条纹并为同一纹理区。
3. **叠加查看**：
   - 「原图」层；
   - 「方向场」层：使用大窗口圆均值平滑后的方向场，色相编码局部方向，饱和度随方向一致性增强（低一致性处退回灰度），每 10px 绘制方向短线，方向杂乱区域不绘制；
   - 「区域轮廓」层：区域半透明着色；**青绿 = 高置信边界（两侧区域方向稳定且直接相邻），红色 = 低置信边界（方向交界带，精确位置不确定），白色 = 候选区与背景的边缘**。两层均可单独调透明度。
4. **保存版本**：填可选备注后点击「保存当前结果」，系统自动递增版本号（v1、v2…），保存当时的阈值参数、区域统计与轮廓结果。点击历史版本可一键恢复该版本的参数并重算查看，可删除不需要的版本。
5. **区域统计**：页面底部表格列出每个区域的像素面积、物理面积（µm²）、外接框宽高、平均方向角、方向对齐度、平均一致性/强度与周长；点击某行在图上黄框定位。

## 算法流程

`server/imageproc.js` 纯 Node 实现（无 Python / OpenCV 依赖）：

1. 3×3 Sobel 计算梯度 `(gx, gy)`；积分图加速的窗口结构张量
   `J = Σ[gx², gxgy; gxgy, gy²]`，特征分解得到窗口梯度能量 `E=√trace J`、
   一致性 `C=(λ₁−λ₂)/(λ₁+λ₂)` 与无向纹理方向角 `θ ∈ [−π/2, π/2)`；
2. `E ≥ 分位截断` **且** `C ≥ 阈值` → 候选纹理掩码；
3. 计算多尺度方向不连续度 `B`（跨 2/4 像素比较纹理方向的最大锐角差）：
   方向一致的纹理内部 `B` 很小，两个不同方向纹理的交界带 `B` 显著升高，
   作为不可穿越的方向屏障（`B ≥ 30°`），这是避免相邻区域粘连的关键；
4. 候选域减去屏障后做形态学腐蚀，每个大块纹理核取一个 4 邻域连通标记
   （4 邻域可防止对角角点渗漏），小标记（<64px）按噪声剔除；
5. **标记控制的分水岭泛洪**：以 `B` 为地形（方向连续处先漫），
   不同水源在方向屏障处相遇成分水线；未覆盖的大块域补为独立区域；
6. **分水岭式合并**：先求各区域的平均纹理方向（`sin 2θ/cos 2θ` 圆均值），
   在标签场上做 12px 多源膨胀，得到跨越非候选间隙（暗间隔/分水线）的区域邻接对；
   仅当两个区域平均方向角差小于合并阈值（`mergeCutoff × 90°`）时
   按代价升序做 Union-Find 合并——同方向被暗隙分开的条纹会合并，
   正交/异方向区域即使相邻也不会合并；
7. **边界置信度**：多源 BFS 让每个非区域像素记录能到达它的区域，
   夹在两个区域之间的屏障带标为**低置信（红）**（边界精确位置不确定）；
   直接相邻的区域公共边按两侧区域的方向对齐度判高/低置信；
   只触及单个区域的候选外缘标为掩码边缘（白）。

## 目录结构

```
.
├── Dockerfile              # 多阶段构建（含原生模块编译回退）
├── docker-compose.yml
├── package.json
├── server/
│   ├── index.js            # Express API、SQLite 存储、图像入库与结果缓存
│   └── imageproc.js        # 方向场 / 阈值掩码 / 方向屏障 / 分水岭 / 合并 / 叠加渲染
├── public/                 # 静态网页（原生 HTML/CSS/JS，无构建步骤）
│   ├── index.html
│   ├── style.css
│   └── app.js
├── test/
│   ├── make-fixture.js     # 合成锐利条纹纹理图
│   ├── make-smooth.js      # 合成连续流动纹理图
│   └── e2e.js              # HTTP API 端到端回归（需先启动服务）
└── data/                   # 运行后生成：workbench.db + images/*.png
```

本地运行回归测试：

```bash
npm start &              # 或任意 PORT
BASE=http://localhost:8080 node test/e2e.js
```

## 主要 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/images` | multipart 上传 `image`，可选 `scale_um_per_px` |
| GET | `/api/images` | 图像列表 |
| GET | `/api/images/:id` | 图像详情与全部已保存版本 |
| PUT | `/api/images/:id/scale` | 修改像素尺度 |
| GET | `/api/images/:id/original.png` | 灰度原图 |
| GET | `/api/images/:id/segment?strengthThresh=&coherenceThresh=&mergeCutoff=` | 实时分割结果（JSON） |
| GET | `/api/images/:id/overlay.png?layer=original\|field\|regions&…` | 三种叠加层 PNG |
| POST | `/api/images/:id/versions` | 保存新版本（自增版本号） |
| GET / DELETE | `/api/images/:id/versions/:version` | 读取 / 删除某版本 |

## 备注

- 工具设计为**本地单机审阅**使用，未加鉴权；请勿直接暴露到公网。
- 分析分辨率上限 1000px（长边）以保证浏览器与 Node 端实时流畅；如需修改调整
  `server/index.js` 中的 `MAX_ANALYSIS_DIM`。
- 上传大小上限 30MB（`MAX_UPLOAD_MB`）。
